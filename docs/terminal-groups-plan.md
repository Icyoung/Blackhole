# Voyager 终端分组功能规划

## 功能概述

为 Voyager 添加终端分组（项目）功能，允许用户将多个终端会话组织到不同的分组中，便于管理多项目场景。

## 用户界面设计

### 1. 左侧抽屉 (Drawer)

```
┌─────────────────────────────────────┐
│  终端分组           [编辑] [+]      │
├─────────────────────────────────────┤
│                                     │
│  ▼ 默认分组 (3)                     │
│     ├─ Terminal 1                   │
│     ├─ Terminal 2                   │
│     └─ Terminal 3                   │
│                                     │
│  ▶ 项目A (2)                        │
│                                     │
│  ▶ 分组1 (1)                        │
│                                     │
└─────────────────────────────────────┘
```

### 2. 抽屉头部按钮

| 按钮 | 功能 | 状态切换 |
|------|------|----------|
| **[+]** | 添加新分组 | 点击后创建 "分组N" |
| **[编辑]** | 进入编辑模式 | 切换为 [保存] |
| **[保存]** | 保存修改 | 切换回 [编辑] |

### 3. 编辑模式功能

- 分组名称可点击编辑（显示为 TextField）
- 每个分组右侧显示删除按钮
- 终端项可拖拽到其他分组
- 长按终端项显示移动菜单

## 数据模型

### TerminalGroup 类

```dart
class TerminalGroup {
  final String id;           // UUID
  String name;               // 分组名称
  List<String> sessionIds;   // 终端会话ID列表
  final DateTime createdAt;

  bool get isDefault => id == 'default';
}
```

### 存储结构 (SharedPreferences / JSON)

```json
{
  "version": 1,
  "groups": [
    {
      "id": "default",
      "name": "默认分组",
      "sessionIds": ["session-1", "session-2"],
      "createdAt": "2024-01-01T00:00:00Z"
    },
    {
      "id": "uuid-xxx",
      "name": "项目A",
      "sessionIds": ["session-3"],
      "createdAt": "2024-01-15T10:30:00Z"
    }
  ],
  "activeGroupId": "default"
}
```

## 交互流程

### 添加新分组

```
用户点击 [+]
  → 创建新分组 { id: uuid, name: "分组N" }
  → 自动进入编辑模式
  → 聚焦到新分组名称输入框
  → 用户修改名称
  → 点击 [保存] 或点击其他区域
  → 保存到存储
```

### 删除分组

```
编辑模式下点击分组的删除按钮
  → 显示确认对话框
  → 确认后:
    → 将该分组的终端移动到默认分组
    → 删除分组
    → 保存到存储
```

### 移动终端到其他分组

```
方式1: 拖拽 (编辑模式)
  → 长按终端项
  → 拖动到目标分组
  → 释放后更新数据

方式2: 菜单
  → 长按终端项
  → 显示 "移动到..." 菜单
  → 选择目标分组
  → 更新数据
```

## 边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 删除唯一分组（默认分组） | 禁止删除，默认分组不可删除 |
| 分组名称为空 | 保存时恢复为 "分组N" |
| 分组名称重复 | 允许重复（通过 UUID 区分） |
| 终端断开连接 | 保留在分组中，显示断开状态 |
| 清空分组 | 允许空分组存在 |

## 技术考虑

### 状态管理

建议使用简单的 ChangeNotifier + Provider 模式，与现有代码风格保持一致。

### 持久化

使用现有的 SharedPreferences，将分组数据 JSON 序列化存储。

### 性能

- 分组数量预期较少（< 20），无需虚拟滚动
- 使用 const 构造函数优化重建
